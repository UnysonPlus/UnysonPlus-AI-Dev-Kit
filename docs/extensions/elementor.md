# elementor extension

Unyson+ elements as native Elementor widgets, edited in Elementor's own side panel (Content / Style / Advanced tabs, live preview, undo, global colours). Every widget renders through its shortcode's own view, so the output is the same markup the page builder produces. **Active by default:** no (inert unless Elementor is active). **Requires:** `shortcodes`. Version: 1.0.4. **53 widgets** (35 content + 18 WooCommerce) — the content elements; layout (section / row / column / container) and plain text (text block, heading, button) are left to Elementor's own widgets.

## Provides

- **Panel category "Unyson+"** (`unysonplus`) holding the widgets.
- **Settings** (Unyson+ → Extensions → Elementor Widgets): **Hide locked Pro widgets** (`hide_pro_promos`, default `yes`). With Elementor Pro inactive it removes the locked Pro tiles (strips `pro_widgets` from Elementor's cached remote info via the `transient_elementor_remote_info_api_data_<ver>` filter — the editor re-merges them after its public `localize_settings` filter, so that one is useless), and hides Elementor 4's Atomic Form promotion category, any other locked tile and the "Access all Pro widgets" banner with an editor-only stylesheet. Nothing is unregistered.
- **Widgets** — name = `'up-' . str_replace( '_', '-', $tag )`. **The name is a stable contract** (the Site Converter writes it into saved documents); renaming one is a breaking change.

- **Public API**
  - `fw_ext( 'elementor' )->widget_for_shortcode( $tag )` → widget name or `''`. Works without the editor (CLI / cron).
  - `FW_Elementor_Option_Bridge::settings_from_atts( $tag, array $atts )` → widget settings. `$atts` = the page-builder atts shape (nested values, multi-picker `{picker, choice: {…}}`, compact colours `{predefined, custom}`, addable rows). Exact inverse of the render path: rendering the settings reproduces the page-builder markup.
  - `fw_ext( 'elementor' )->get_widget( $tag )` → the widget instance (`build_atts( $settings )`, `settings_from_atts( $atts )`).
- **Filter** `fw_ext_elementor_widgets` — `tag => [ 'file' => …, 'class' => … ]`, the widget registry.
- **Test** `tests/settings-round-trip-test.php` — every snapshot node with a widget: atts → settings → atts (strict), shortcode vs widget markup (each side in its own process), and a `Document::save()` page rendering on the front end. Run: `php wp-cli.phar --path=<install with Elementor> eval-file <test>`.

## Adding a widget

One file `widgets/<name>.php` with a class extending `FW_Elementor_Shortcode_Widget`, plus a registry row in `get_widget_files()`:

- `shortcode_tag()`, `get_title()`, `get_icon()` (an `eicon-*`), `get_keywords()`.
- `sections()` — `[ [ 'id', 'label', 'tab' => 'content'|'style', 'options' => [ option ids ] ], … ]`. Expose option ids from the shortcode's `options.php`; the bridge builds the controls. Leave out the shortcode's Advanced / Animation tabs — Elementor's own Advanced tab covers the wrapper.
- `control_overrides()` — `path => partial control args` (a starter `default` for a repeater, a `title_field`).
- If the element has a script, make sure it registers on `window.fwShortcodeInit` (see `../extending.md` → shortcode conventions). `widgets.js` runs every entry on each `up-*` widget Elementor reports ready; there are no per-widget handlers.
- Starter `default` rows for a repeater use CONTROL names and values (`price__monthly`, a switch off = `''`), not atts.
- Run the round-trip test.

**Option type → control:** text/short-text → TEXT · textarea → TEXTAREA · wp-editor → WYSIWYG · number/slider → NUMBER · switch → SWITCHER (`return_value` = the right-choice value) · radio/select/short-select/border-style-picker/button-style-picker/table-style-picker/image-style-picker → SELECT · multi-select / checkboxes → SELECT2 multiple (checkboxes stored as `{key: true}` for the ticked keys) · datetime-picker → DATE_TIME (`Y/m/d H:i`, the page builder's format) · popover with one inner option → that option, under the popover's label · image-picker → VISUAL_CHOICE (thumbnails), CHOOSE with align icons (`sc-alignment` pickers), or SELECT (an empty-key choice) · upload → MEDIA · multi-upload → GALLERY (`[{attachment_id, url}]` ↔ `[{id, url}]`) · form-builder → `<name>__fields` REPEATER (see Notes) · table → hidden `<name>__meta` (header options + columns) + `<name>__rows` REPEATER (row type, cells one per line) · color-picker → COLOR · icon → ICONS (font icons both ways; an Elementor SVG pick becomes a `custom-upload` icon; emoji / Lottie / Rive / inline SVG stay in the residue) · unit-input → SLIDER with the option's units (`{value, unit}` ↔ `{size, unit}`) · compact colour → preset SELECT + `<name>__custom` COLOR · multi-inline → one control per part, `<name>__<key>` · addable-popup/box → REPEATER (one level) · multi-picker → picker control + every choice's controls gated by `condition`. Unmapped types (typography, spacing, animation, hidden…) are skipped; they keep the shortcode default, or the value carried in the residue. Control name = option path with `/` → `__`.

## Notes / gotchas

- **Residue (`up_extra_atts`, per row `up_item_extra`).** Hidden settings holding whatever the controls cannot carry: unexposed options (unique id, custom CSS, spacing, animations), legacy keys, nested lists, values a control would retype. `build_atts()` = shortcode defaults ← widget id as `unique_id` ← controls ← residue. A `unique_id` carried in from page-builder atts wins, so custom CSS scoped to it keeps matching.
- **Never put classes in the extension's `includes/`** — the framework includes every file there at load, before Elementor exists, and `extends \Elementor\Widget_Base` fatals the site. The classes live in `lib/` and load on demand.
- **A multi-picker's picker needs a default.** It usually declares none (the multi-picker's value carries it); without one no choice's condition is met and Elementor reports every design option as inactive.
- **Inactive controls come back as `null`** from `get_settings_for_display()`; the bridge leaves them to the shortcode default instead of reading them as "off". For the same reason a compact colour's custom control has no condition.
- **Editor re-renders arrive as nodes from the editor's window.** `node instanceof HTMLElement` is false in the preview frame, and Splide then reports "A track/list element is missing" for markup that is all there. `widgets.js` walks the widget down to the first foreign nodes (they can sit below wrappers the frame built itself) and imports them into the frame's document before running the inits.
- **Table codec.** `table_to()` / `table_from()`: header options and the column list ride in `<name>__meta`; each row is `{ row, cells }` with the cells joined by newlines. The column list follows the widest row (padded with `default-col`, trimmed). `header_rows` is re-derived from the leading heading rows when it was derived that way originally (`auto_header`), so changing a row's type moves the header. A row whose cells carry more than text (amount / button / switch, colspan / merged, a newline inside a cell) keeps them in its `up_item_extra` and renders exactly — but those cells are edited in the page builder's table editor. The table option declares no default, so `table_from()` fills `table_purpose: tabular` / `footer_rows: 0` when the meta lacks them (without a purpose the view renders nothing).
- **Form codec.** The value is `{ json: "[ {type, shortcode, width, options}, … ]" }`. Each field → a row (`field_type`, `label` — a heading's title, `subtitle`, `required`, `placeholder`, `choices` one per line, `width`), each control shown only for the types that use it; everything else rides in the row's residue. `shortcode` is the field's name in submissions: a carried-in field keeps its own, a field added in the panel gets `<type>_<row _id>`. The residue compares JSON strings by **content** (`same_json()`), so another encoder's key order / escaping is not a change. The widget pins the form `id` (a `unique` option — random per render otherwise, and the forms extension stores the form's settings under it on every render) to `el<widget id>` unless one was carried in, and starts addressed to the site admin email (the extension refuses to send with no recipient: "Unable to process the form").
- **Editor context.** Elementor's preview is a front-end request, so core's `fw_is_editor_context()` said "visitor" there and an element with nothing to show yet rendered nothing (Elementor then drops it). Core now has a `fw_is_editor_context` filter; this extension answers true in Elementor's preview mode, so empty-state hints show (Lottie / Video Popup without a source).
- **Elements with no options** (cart, checkout…) still get one Content section — the residue control lives in the first section — holding a note instead of controls.
- **Context-dependent shop elements** (Upsells needs a product, Wishlist / Compare a visitor's list, Free Shipping a cart, Product Filters a shop / category archive) render nothing on an ordinary page; they show their editor hint in Elementor's preview (via the `fw_is_editor_context` filter) and Elementor would otherwise drop them.
- **Starter content.** A widget whose element renders nothing without content gets starter rows / an image in `control_overrides()`; `placeholder_image()` gives Elementor's placeholder as a MEDIA value. Upload values are no longer filtered for the placeholder (our controls never default to it on their own).
- **Elementor drops a widget whose render is empty** (`should_render` false) — an empty list, a missing purpose, or a view that returned early all look like "the widget vanished". Trace it with the `elementor/frontend/widget/should_render` filter.
- **Shortcode view helpers must have unique names.** Views define their render helpers behind `function_exists()`, so two elements choosing the same name share whichever loaded first. `timeline` and `tag-list` both defined `sc_tl_render()`: on any page (page builder or Elementor) a Tag List after a Timeline called the timeline's renderer and printed nothing. Renamed to `sc_timeline_render()` / `sc_taglist_render()`. Prefix a view helper with the element's full name.
- **Switch values:** SWITCHER stores `''` for off. `from_elementor()` also reads the option's own off value (`'no'`, `false`) as off, so hand-written settings cannot flip a switch on by accident.
- **Asset optimizer bundles can run after Elementor's `elementor/frontend/init`.** `widgets.js` registers immediately when `elementorFrontend.hooks` exists, and on the event otherwise.
- **Assets:** front end — a `<head>` pass reads `_elementor_data`, and for each `up-*` widget enqueues its `static.php` set, fires the shortcode's per-instance action `fw_ext_shortcodes_enqueue_static:<tag>` with the instance's atts encoded by the page builder's JSON coder (atts-dependent assets hang there — the logo carousel's Splide + mount script), and enqueues the design stylesheet through the same `fw_sc_design_enqueue_now()` handle the view uses, so the two dedupe. Render repeats the first two for placements the head pass cannot see. Editor preview — every widget's assets, the per-instance action once per choice of each exposed picker-like option (design, layout), and every design's stylesheet load up front (AJAX re-renders cannot enqueue).
- **Elementor pages expose shortcode CSS that leaned on a global reset or a weak selector.** Two found so far, both fixed in the shortcode's own CSS so every surface benefits: the testimonial `<blockquote>` kept the browser's 40px side margin (now `margin: 0 0 1rem`), and the pricing button label lost to a theme `a:not(.btn)` colour (now scoped `.fw-pt .fw-pt__btn`). A third, in the newsletter: the boxed panel was a fixed light grey and the fields white with inherited text, so a dark theme put light headings on a light box and white text in white fields — the panel is now a tint of the text colour and the fields carry their own dark text. This round: the TOC panel and the comparison table had the same fixed-light-surface problem (now tints / paired header text), and the TOC's content auto-detect took the first `.entry-content` on the page — a posts grid card's — and hid itself; it now prefers a content area that contains the TOC, and knows Elementor's document wrapper. Form results (flash messages) now print right above the form instead of at the top of the body, under a fixed header. Check each new widget for the same (blockquote / figure / list padding / heading margins / link colours / fixed light surfaces under inherited text).
- **A document written with `Document::save()` also needs `$document->set_is_built_with_elementor( true )`**; the editor sets it, `save()` does not, and without it the theme renders `post_content`. `save()` also checks the current user can edit the post (set one under WP-CLI).
- **Registration:** widgets register on `elementor/widgets/register`, which fires on any request that builds the widgets manager, CLI included, so `Document::save()` keeps `up-*` elements. Elementor drops unregistered widget types silently; check `widget_for_shortcode()` first.
