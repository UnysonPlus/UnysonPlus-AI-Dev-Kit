# visitor-insights extension

Self-hosted, privacy-first visitor analytics: traffic without cookies, click / scroll / attention heatmaps drawn over the live page, and reach + attention for every page-builder section. **Active by default:** no (activate under **Unyson+ → Extensions → Visitor Insights**). Admin screen: **Unyson+ → Visitor Insights** (tabs: Overview · Pages · Heatmaps · Goals · Funnels · A/B tests · Forms · Search · Frustration · Performance · Recordings · Live · Settings). It is the ONLY settings screen: the Extensions card's Settings link points at its Settings tab (`fw_ext_manager_settings_url`), and the manager's generic form redirects there. Roadmap (status verified against this source tree): `unysonplus-site/src/data/visitor-insights-roadmap.json`, published at `/extensions/visitor-insights/roadmap`. All four roadmap phases are built: traffic, heatmaps, section analytics; goals, funnels, frustration & errors, real-visitor performance; form analytics, site search, section A/B tests, weekly email, AI Assistant abilities; consent-only session recording.

## Provides

- **Data path:**
  1. `static/js/vi-core.js` (+ `modules/heatmaps.js`, `modules/sections.js`) — the tracker; ~4 KB gzipped together. Starts in `requestIdleCallback` after `load`, only when the consent rules allow (below). Batches events and sends them with `sendBeacon` (fallback `fetch` keepalive): first batch at once (it carries the page view), a second at 3 s, then every 10 s and on `visibilitychange → hidden` / `pagehide`.
  2. `collector/collect.php` — the standalone collector. **Does not boot WordPress**: finds the content dir by walking up to the folder holding `uploads` + `plugins`/`themes`, reads `uploads/unysonplus/visitor-insights/config.php` (`uploads/sites/{b}/…` for a multisite subsite, `?b=` in the URL), runs `FW_VI_Ingest::handle()`, appends one line to `buf-{key}-{YmdHi}.php` (file starts with `<?php exit; ?>`), returns 204.
  3. REST `POST fw-visitor-insights/v1/collect` — the same `FW_VI_Ingest::handle()` inside WordPress (+ shared `fw_rate_limit_exceeded( 'fw_vi_collect', 120, 60 )`). Used automatically when the direct collector fails its self-test (`FW_VI_Collector::self_test()`, run whenever the config is rewritten; result in option `fw_ext_vi_endpoint` = `direct`|`rest`).
  4. `FW_VI_Rollup::run()` — WP-Cron every minute (schedule `fw_vi_minute`, hook `fw_ext_vi_rollup`) AND on every admin page load of the screen / every report REST call. Reads only closed minutes, sums in memory, writes multi-row `INSERT … ON DUPLICATE KEY UPDATE`, deletes the file. Lock: atomic `add_option( 'fw_ext_vi_rollup_lock' )`, stale after 300 s.
  5. `FW_VI_Retention::run()` — daily (`fw_ext_vi_daily`): deletes days older than `retention_days` (batched 5,000), deletes `fw_vi_uniq` rows before today, rotates the visitor salt, clears buffer files > 24 h (sets option `fw_ext_vi_stale_buffer` → admin notice).
- **Wire format** (POST body, `text/plain` JSON, ≤ 16 KB): `{v:1, p:post_id, u:path, k:token, i:view_id, q:seq, d:'d'|'t'|'m', pv?:{r,us,um,uc}, e:[…]}`. Events: `['c', item, ox, oy]` click in a builder item (10% cells) · `['c', '', cx, cy]` click outside any item (% of page width, 20 px rows) · `['s', band]` scroll band 0–100 step 5 first reached · `['r', item]` section reached · `['a', item, ms]` section in-view time delta · `['t', ms]` engaged-time delta · `['g', key, value]` goal (≤ 20/batch) · `['f', r|d|e, item|'']` rage / dead / error click · `['x', message, source, line]` script error (masked, ≤ 5/batch) · `['v', lcp|inp|cls|ttfb, value]` Web Vital (once each; cls × 1000) · `['fs', form, label]` / `['ff', form, field, pos]` / `['fc', form]` / `['fa', form, last_field]` form started / field first focused / sent / abandoned (≤ 60/batch; keys `[A-Za-z0-9_.:-]`) · `['e', experiment, a|b]` A/B exposure. Server-only (seq -1): `['q', term, results]` site search. **seq -1 lines** are written by WordPress itself (`FW_VI_Collector::server_line()`: server-side goals `['g', key, value]` and 404s `['n', ref]`); the collector rejects negative seq, so a browser can't forge them. Device = viewport width (< 768 m, < 1025 t, else d). Anything malformed is dropped per event.
- **Page token:** `FW_VI_Ingest::token( secret, post_id, path, Ymd_utc )` = first 16 hex of HMAC-SHA256. Minted per page render (`FW_VI_Collector::token()`), accepted for today + 7 previous days, so a cached page keeps reporting. No nonces anywhere on the ingest path.
- **Tables** (`$wpdb->prefix`, `FW_VI_Installer`, option `fw_ext_visitor_insights_db_version`; never dropped on deactivate). All report tables are pre-aggregated, PK led by `(page_id, day, …)`; `day` is site-local:
  - `fw_vi_pages` — `id`, `post_id` (0 for archives etc.), `path` (UNIQUE, request path without query, ≤ 191).
  - `fw_vi_views` — `(page_id, day, device)` → `views`, `uniques`, `engaged_ms`. **`page_id` 0 = site-wide totals** (uniques can't be summed across pages). Uniques are per page/day, credited to one device row.
  - `fw_vi_sources` — `(page_id, day, dim, val)` → `n`; `dim` = `ref` (external referrer host) · `us`/`um`/`uc` (UTM) · `cc` (country, CDN headers only) · `br` · `os` · `dev`.
  - `fw_vi_elem` — `(page_id, day, device, item, ox, oy)` → `n`. `fw_vi_clicks` — `(page_id, day, device, cx, cy)` → `n`.
  - `fw_vi_scroll` — `(page_id, day, device, band)` → `n` = views that reached ≥ band %.
  - `fw_vi_sections` — `(page_id, day, device, item)` → `reached`, `visible_ms`.
  - **1.1.0:** `fw_vi_goals` — `(page_id, day, device, goal)` → `n`, `value` (cents). `fw_vi_funnel_progress` — `(day, funnel, vh)` → `step` (today only, deleted with the salt). `fw_vi_funnel_daily` — `(day, funnel, step)` → `n`. `fw_vi_friction` — `(page_id, day, device, item, kind)` → `n`. `fw_vi_errors` — `(page_id, day, hash)` → `n` + `fw_vi_error_msgs` (`hash` → message, source, line; orphans pruned nightly). `fw_vi_404` — `(day, path, ref)` → `n` (`ref` = host, `internal`, or ''). `fw_vi_vitals` — `(page_id, day, device, metric, bucket)` → `n`. `fw_vi_live` gained `vh` (resolves the visitor of later goal batches for funnels).
  - **1.2.0:** `fw_vi_forms` — `(page_id, day, form)` → `label`, `starts`, `submits`, `abandons`. `fw_vi_form_fields` — `(page_id, day, form, field)` → `pos` (max), `touched`, `lastn`. `fw_vi_search` — `(day, term)` → `n`, `zero`. `fw_vi_exp_assign` — `(day, exp, vh)` → `last`, `seen`, `converted` (today only). `fw_vi_exp_daily` — `(day, exp, variant)` → `visitors`, `conversions`.
  - `fw_vi_uniq` — today's visitor hashes only (`INSERT IGNORE` → `rows_affected` = new uniques). `fw_vi_live` — `vid` → `page_id`, `device`, `seen` (pruned after 10 min).
- **Builder ids on the page:** `FW_VI_Element_IDs` stamps `data-fw-item-id="<unique_id>"` (same attribute as the Live Editor) through `sc_build_wrapper_attr` (priority 998) and a `do_shortcode_tag` fallback for theme-overridden views — **only when `FW_VI_Front::mode()` is `track` or `view`**, so untracked pages keep their clean DOM. `unique_id` is unique per post, so the key is page + item. Sections = top-level `section[data-fw-item-id]`.
- **`FW_VI_Front::mode()`** (resolved after `wp`): `''` for admin / AJAX / cron / REST / feeds / previews / Customizer / robots / 404 / Live Editor (`fw-live-editor`, `fw-live-editor-frame`) / cart / checkout / account / `excluded_paths` (fnmatch) / logged-in `edit_posts` users unless `track_editors`; `view` for `?fw_vi_view=<nonce 'fw_vi_view'>` by a user who `can_view()`; else `track`.
- **Heatmap view** (`FW_VI_Heatmaps`): the live page with `?fw_vi_view=<nonce>` (+ `fw_vi_frame=1` when framed in the Heatmaps tab — admin bar hidden on `wp` priority 99, before the bar initialises). Never cached (`DONOTCACHEPAGE`, `nocache_headers()`), never tracked, skipped by the Asset Optimizer (`fw_ao_editor_query_vars`). `static/js/admin/heatmap-viewer.js` draws on two fixed viewport-sized canvases (base + vendored simpleheat 0.4.0, BSD-2, `LICENSES.md`), redrawn on scroll/resize; modes: clicks · scroll reach · attention · elements (top 25 items by click share). Framed: driven by `postMessage` `upvi:show` {mode, device, days}, answers `upvi:ready` / `upvi:info` {views, clicks, missing, sections[]}. Admin-bar **Heatmap** link opens it full size with its own toolbar (the fallback when framing is blocked).
- **Live Editor:** in the canvas (`fw-live-editor-frame`), `static/js/live-editor-overlay.js` adds a **Heatmap** button that lazy-loads the viewer in `embedded` mode (close = `destroy()`, canvas untouched). **Backend builder:** on `post.php` of a published post with data, `static/js/admin/builder-badges.js` prepends a `.fw-vi-badge` (reach % for sections, share of clicks for items; last 30 days, all devices) on the `fw:page-builder:shortcode:*:controls` events, joined on `model.get('atts').unique_id`.
- **Goals** (`FW_VI_Goals`, keys `[a-z0-9_-]{1,40}`; only known, enabled keys are counted at rollup): **element** — `vi_goal` text field added to every element's Advanced tab through the shortcodes filter `sc_advanced_tab_options`; on tracked pages the wrapper gets `data-fw-vi-goal="<key>"` (both stamping paths) and the key is registered in option `fw_ext_vi_goal_elements` on first render; `modules/goals.js` pushes `['g', key, 0]` and flushes at once. **page** — option `fw_ext_vi_goals` (`type` page, `pattern` with `*`; matched by `FW_VI_Goals::path_matches()`, which also tries the pattern under the site's home path). **event** — same option, `type` event; `UnysonPlusVI.goal( key, value )`. **integration** (`FW_VI_Integrations`, switchable via option `fw_ext_vi_goal_integrations`): `form_submit` (`fw_ext_forms_frontend_submit`), `newsletter_signup` (`unysonplus_newsletter_crm_subscriber_added`, not from admin/cron/CLI/import contexts), `woo_order` (`woocommerce_checkout_order_processed` + `woocommerce_store_api_checkout_order_processed`, once per order via meta `_fw_vi_goal`, value = total in cents), `short_link_click` (`fw_ext_short_links_click`). Server-side goals are credited to the referring page on this site. Rate on the Goals tab = completions per page view (completions are counted per occurrence, not per visitor).
- **Funnels** (`FW_VI_Funnels`, option `fw_ext_vi_funnels`, ≤ 10 funnels, 2–6 steps of `page` / `goal`): the rollup collects touchpoints (page views + goals with a visitor hash, sorted by time) and advances `fw_vi_funnel_progress`; a step counts only after every earlier step, same site-local day, other pages allowed between. Visitors sharing address + browser count as one. With `consent_mode = require`, server-side goals carry no hash (they can't know consent) so they count but never advance funnels.
- **Frustration & errors** (`modules/frustration.js`, `FW_VI_Errors`): rage = 3 clicks each < 1 s and < 30 px (Manhattan) apart, once per burst; dead = a click on something that looks clickable (`button`, `[role=button]`, `[onclick]`, `cursor:pointer`; never links/fields/modifier clicks) with no response in 2.5 s — response = any childList/characterData mutation, a state attribute (`open`, `hidden`, `aria-expanded` …) anywhere, a class/style change on the clicked element or its relatives, a scroll or a non-collapsed selection within 100 ms, or the page being hidden; error click = script error < 1 s after a click. Error listeners attach when the file loads (errors during load are kept in memory and sent only once tracking starts). 404s: `template_redirect` priority 99, skips probe noise (`FW_VI_Errors::NOISE`: `.php`, `.env`, backups, dotfiles, wp-admin …).
- **Performance** (`modules/vitals.js`, `FW_VI_Vitals`): PerformanceObserver (`buffered`) for LCP (not for pages loaded hidden), CLS session windows, INP (event entries ≥ 40 ms grouped by interactionId; p98 for 50+ interactions), TTFB (minus `activationStart`). Sent once on first hide. Histogram buckets: lcp/ttfb 100 ms (cap 10 s), inp 25 ms (cap 2 s), cls 0.01 (cap 1.0); p75 reported as the bucket's upper edge. Thresholds: LCP 2.5/4 s, INP 200/500 ms, CLS 0.1/0.25, TTFB 0.8/1.8 s.
- **Form analytics** (`modules/forms.js`, `FW_VI_Form_Analytics`): every `<form>` except search forms (`role=search`, `input[type=search]`, `name=s`) and the admin bar. Key = enclosing builder item id, else `id-<id>`, `name-<name>`, `form-<n>`. Label = `aria-label`, an inner legend/heading, else the nearest heading with text before the form. Fields = inputs (not hidden/submit/button/image/reset), selects, textareas, keyed by name / id / type-index. Abandon is sent only when the page is really left (`api.leaving()`, set by `pagehide`), not on a tab switch. Values are never read.
- **Site search** (`FW_VI_Search`): `template_redirect` priority 98 on `is_search()`, first results page only; term = `FW_VI_Ingest::mask()` + lower-case, ≤ 80; written as a seq -1 line with `found_posts`. Search pages are tracked as one page, path `<base>/?s=`.
- **Page paths** (`FW_VI_Front::path()`): query strings are dropped EXCEPT `p`, `page_id`, `cat`, `tag`, `author`, `post_type`, `product` (plain-permalink sites) and `s` (kept as `s=` with no term). Before 1.0.2 these all collapsed into the home page.
- **A/B tests** (`FW_VI_Experiments`, option `fw_ext_vi_experiments`): `{name, post_id, a, b (section unique_ids), goal, status running|stopped, winner ''|a|b, created}`. `wp_head` priority 1 prints `<style id="upvi-x">` (`html:not(.upvi-x-<id>-b) [data-fw-item-id=B]` and `html.upvi-x-<id>-b [data-fw-item-id=A]` → `display:none!important`; no JS = A) and, while running, a script that picks a/b per page view with `Math.random()`, adds the class to `<html>` and sets `window.UPVIX`. Skipped in the admin, the Live Editor and heatmap views. `FW_VI_Element_IDs` stamps ids on such pages even when not tracked. `modules/experiments.js` sends `['e', id, v]`. Rollup (`FW_VI_Experiments::process`, after funnels, same touchpoints): visitors = distinct (day, vh) per variant seen; a conversion = the experiment's goal by that vh the same day, once, credited to the variant seen LAST. Confidence = two-proportion z-test, two-sided (A&S erf); a winner is called at ≥ 0.95, with < 100 visitors shown as "too early". Stopped with a winner → CSS keeps hiding the loser (delete it in the builder). Sections are picked from `FW_VI_Sections::items_of( $post_id )` (builder JSON → `unique_id` → type, label, section, parent).
- **Weekly email** (`FW_VI_Digest`): settings `digest` (default off), `digest_to` (comma list; empty = admin email). WP-Cron `fw_ext_vi_digest`, `weekly`, first run next Monday 08:00 site time; unscheduled when switched off. Last 7 full days vs the 7 before: views, visitors, goal completions (± %), top pages, internal 404s, frustrated pages, script errors, phone p75 vitals. "Send me a test" on Settings → `FW_VI_Digest::send( [current user email] )`.
- **AI Assistant** (`FW_VI_AI`, on `fw_ai_assistant_register_abilities`): read-only `unysonplus/visitor-insights-overview` `{days}` and `unysonplus/visitor-insights-page` `{post_id | path, days, device all|d|t|m}` (panel: true). Permission = `FW_VI_Settings::can_view()`. Elements and sections are named from the builder data.
- **Session recording** (`FW_VI_Recordings`, `static/js/recorder/recorder.js`, vendored `static/js/vendor/rrweb/` 2.1.7 — `record.min.js` front, `rrweb-player.min.js` + css admin; MIT in `LICENSES.md`). Off by default (`recording`). Consent ALWAYS required: `rec_consent` `api` = `wp_has_consent('statistics')` (note: not the anonymous category) with an active consent type, or `manual` = `UnysonPlusVI.grantRecording()`; never with GPC or the opt-out key; `UnysonPlusVI.stopRecording(forget = true)` and a consent withdrawal stop rrweb and POST `/rec/forget`. The loader is enqueued only on `track` pages not matching `rec_exclude`; the library loads only after consent + sampling (`rec_sample`, decided once per session). Session = sessionStorage `upvi_rec` `{sid (24 [a-z0-9]), seq, t, on, sampled, optout}`, 30-minute idle. rrweb options: `maskAllInputs: true`, `maskTextSelector: '*'` when `rec_mask_text`, `maskTextClass: 'up-vi-mask'`, `blockClass: 'up-vi-block'`, no canvas / fonts / inline images, sampling mousemove 50 / scroll 150 / input 'last' / media 800, slimDOM. Batches: every 10 s or ~300 KB, gzipped with `CompressionStream` (`X-UPVI-Enc: gzip`); on hide/pagehide uncompressed with keepalive (< 60 KB). Payload `{v:1, sid, seq, p, u, k (page token), d, f (flags r/d/e/x/g from api.onPush), ev}`. `POST /rec` (public): enabled, ≤ 2 MB body, ≤ 8 MB inflated, bot / logged-in / GPC / rate-limit (60/min) checks, page-token check (`FW_VI_Ingest::token_ok`), per-session cap 15 MB and 2 h. Files: `uploads/unysonplus/visitor-insights/rec/<option fw_ext_vi_rec_key>/<sid>/<seq>.gz` (deny-all .htaccess + index.php on both levels). Table `fw_vi_recordings` (sid PK, started, last_seen, device, country, first_path, paths JSON ≤ 50, pages, chunks, bytes, flags, ev_first/ev_last ms → length). `GET /rec/<sid>` (cap filter `fw_ext_visitor_insights_recordings_cap`, default `manage_options`) merges + sorts events and logs the view (option `fw_ext_vi_rec_log`, last 200). Prune (nightly on `fw_ext_vi_daily` + on opening the tab): `last_seen` older than `rec_retention` days; with `rec_only_problems`, finished sessions (idle + 1 h) without r/d/e/x flags. "Remove all data" deletes every recording. Shortcode `[visitor_insights_recording]` shows whether this tab is recorded and a "Delete my recording" button. Privacy-policy text gains a recording paragraph while recording is on. Tested: the typed values reach the server only as `*` runs.
- **Phase 5 (1.0.4):** **channels** — `FW_VI_Channels::classify( ref, utm_source, utm_medium )` → `paid` (medium cpc/ppc/cpm/paid…/display/banner/ads/affiliate) › `email` (email/newsletter in medium or source) › `campaign` (any UTM) › `direct` (no referrer) › `search` / `ai` / `social` (host lists, whole-label matching: a needle ending in "." matches any suffix, others match the host and its subdomains; filter `fw_ext_visitor_insights_channel_hosts`) › `referral`; the rollup stores it as `fw_vi_sources` dim `ch` (from 1.0.4 on; earlier days have none). **Dashboard widget** `fw_vi_dashboard` (can_view). **CSV export** `admin-post.php?action=fw_vi_export&type=pages|sources|goals|daily&days=N` (nonce `fw_vi_export`, can_view; BOM; cells starting = + - @ tab CR prefixed with '). **Cache clearing** `FW_VI_Cache::purge()` after settings save and A/B add/stop/delete: calls the common page-cache plugins' clear-all functions/actions when present, always fires `fw_ext_visitor_insights_purge_cache`. **Movement maps** (`track_moves`, default off): `modules/moves.js`, `(pointer: fine)` only, 150 ms samples after ≥ 10 px, ≤ 400 per view, binned in the browser to `['m', item|'', a, b, n]` (item cell 0–9, or page grid % / 20 px rows), table `fw_vi_moves` (schema 1.4.0), heatmap mode `moves` ("Movement", shown when enabled).
- **Phase 6 (1.0.5):** **comparison** — `FW_VI_Reports::previous_range( $days )`, `totals_between( $from, $to )`, `change( $now, $before )` (HTML delta); Overview tiles and the pages table (`$row->prev`) show it. **Channel performance** (`FW_VI_Segments`): table `fw_vi_chdaily` `(page_id, day, ch)` → `views, engaged_ms, half, goals` (page_id 0 = site); the rollup credits seq-0 views directly and later `t` / band-50 `s` / `g` events through the view's channel (`$vidch` in the run, else `fw_vi_live.ch`, a column added in 1.5.0); Overview card "How each channel performs"; Pages tab `&ch=<channel>` re-ranks by that channel's views. **Annotations** (`FW_VI_Annotations`, option `fw_ext_vi_annotations`, ≤ 300 `{id, date, note, user}`): actions `note_add` / `note_delete` (dispatched for tab `overview`), markers drawn on the chart. **Recordings per page**: `FW_VI_Recordings::counts_by_path()` / `count_for( $path )`; Recordings tab `&rec_path=` filters by `paths LIKE '%"<path>"%'`. **Alerts** (`FW_VI_Alerts`, setting `alerts`, default off; WP-Cron `fw_ext_vi_alerts` daily 07:30): yesterday vs the 7 days before — views < 50 % of a usual ≥ 50, views > 3× a usual ≥ 20, script errors ≥ 10 and ≥ 3×, a new error hash ≥ 5, internal 404s ≥ 5 and ≥ 3×; one email a day to the digest recipients (option `fw_ext_vi_alerts_last`); "Check yesterday for alerts now" on Settings runs `check()` and shows the result.
- **Phase 7 (1.0.6):** **heatmaps by channel** — table `fw_vi_hmch` `(page_id, day, device, ch, kind, item, a, b)` → `n`, kinds v/e/c/s/r/t/m/f (see the installer comment); the rollup queues every heatmap signal with its view id (`$hq`) and `credit_channels()` writes it under the view's channel; `FW_VI_Heatmaps::data( $path, $device, $days, $ch )` → `data_for_channel()` returns the normal shape; `GET /heatmap?ch=`; `channel_choices()` feeds the menus (Heatmaps tab `data-name="ch"`, viewer toolbar, Live Editor overlay). Channel maps exist from 1.0.6 on. **Image export** — vendored `static/js/vendor/html2canvas.min.js` = html2canvas-pro 2.4.5 (MIT; the original 1.4.1 throws on CSS `color()` / `oklch()`), lazy-loaded via `UPVIV.h2c`; `exportImage()` renders `document.body` at scale 1 (height capped at 12 000 px, overlays and admin bar ignored), redraws the map on page-size layers by switching the viewer's globals (`bctx`, `heat`, `dpr`, offsets `OX`/`OY` added through `box()`), prepends a caption strip. Framed: posts `{type:'upvi:image', blob, name}` to the admin page, which calls `a.click()` and leaves a "Save image" button (a download started inside the frame after the async render is not reliably allowed). Standalone/embedded: `offer()` adds a "Save image" link to the toolbar. Admin page sends `{type:'upvi:export'}`. **Verified:** a real store-API checkout writes one `['g','woo_order', cents]` server line credited to the checkout page (re-firing both hooks adds nothing); the weekly email and an alert are delivered over SMTP. Note: on a host whose site domain has no dot (e.g. `localhost`) WordPress's default sender `wordpress@localhost` is rejected by PHPMailer, so test mail needs a `wp_mail_from` filter there.
- **REST `fw-visitor-insights/v1`:** `POST /collect` (public) · `GET /heatmap?path&device&days` and `GET /live` (permission `FW_VI_Settings::can_view()`; both run the rollup first).
- **Consent** (`FW_VI_Consent`; decided in the browser, never in PHP, because of page caches): opted out (`localStorage.upvi_optout = '1'`) → never · GPC when `honor_gpc` → never · a WP Consent API plugin active (`wp_has_consent` + `wp_consent_type`) → `wp_has_consent( 'statistics-anonymous' )`, re-checked on `wp_listen_for_consent_change` / `wp_consent_type_defined` · otherwise `consent_mode` `auto` tracks, `require` waits for `UnysonPlusVI.grant()`. Declares `wp_consent_api_registered_{unysonplus/unysonplus.php}`; lists the opt-out key via `wp_add_cookie_info()`. Shortcode `[visitor_insights_optout]`.
- **JS API** (`window.UnysonPlusVI`): `grant()`, `revoke()`, `optOut()`, `optIn()`, `module( fn( api ) )` — `api.push(ev)`, `api.on()`, `api.onFlush(fn)`, `api.docHeight()`, `api.visible()`, `api.itemOk(id)`.
- **Privacy:** `wp_add_privacy_policy_content()` text. No exporter/eraser by design — nothing stored is linkable to a person (the per-visitor hash lives one day, with its salt).
- **Settings** (`settings-options.php`, defaults in `FW_VI_Settings::defaults()`): recording `recording`, `rec_consent` (api|manual), `rec_sample` (10/20/50/100, default 20), `rec_only_problems`, `rec_mask_text`, `rec_retention` (7–90, default 30), `rec_exclude`; module switches `track_frustration`, `track_errors`, `track_404`, `track_vitals`, `track_forms`, `track_search` (all default on; the tracker gets `UPVI.mods`), `logged_in` (`visitors` = track logged-in users except those who can `edit_posts` — default; `none`; `all`; replaces 1.0.1's `track_editors`, whose `true` maps to `all`; checked by `FW_VI_Settings::skip_current_user()` for page views AND server lines), `digest`, `digest_to`, `enabled`, `sample_rate` (100/50/25/10, per page view; reports show sampled numbers), `track_editors`, `excluded_paths`, `consent_mode` (`auto`|`require`), `honor_gpc`, `retention_days` (90/180/395/730, default 395), `daily_cap` (views per page per day, default 5000, 0 = none), `excluded_ips`, `trusted_proxies`. Saving rewrites the collector config and re-runs the self-test. Filter `fw_ext_visitor_insights_view_cap` (default `manage_options`) opens the reports to other roles.

## Notes / gotchas

- **`wp_localize_script()` stringifies top-level scalars** — `UPVI.p` / `UPVI.sample` arrive as strings and are `parseInt`ed in `vi-core.js`; the ingest requires integers and rejects a string post id with 400.
- **Never add a nonce to the ingest path.** Cached pages serve stale nonces; the HMAC page token is the replacement. A token is bound to post id + path, so it can't be replayed onto another page.
- **Collector files:** `config.php` holds the secret — it starts with an `ABSPATH`/`FW_VI_COLLECTOR` exit guard and the folder has a deny-all `.htaccess`; buffer files are `.php` with an exit header and a random key in the name, so nginx (which ignores `.htaccess`) still never serves them.
- **The collector reads `$_SERVER` directly** (UA, Origin, proxies) — both the standalone file and the REST route; `FW_VI_Bot_Filter` and `FW_VI_Ingest` must stay free of WordPress calls (guard: `FW` or `FW_VI_COLLECTOR`, `class_exists`).
- **Origin check** rejects (403) a present `Origin` header that is not one of `home_url()`/`site_url()` hosts ± `www.`; a missing Origin is allowed (same-origin `sendBeacon` may omit it).
- **Bots** are dropped silently (204): empty UA, `Sec-Purpose: prefetch`, the shared UA regex; the tracker also refuses to start under `navigator.webdriver`. Test scripts must override `navigator.webdriver` and send a non-headless UA.
- **Clicks on elements that were removed** after the data was recorded can't be placed; the viewer reports their count. Page-grid clicks re-project by page width, not element.
- **Section in-view time** counts while ≥ 50 % of the section is visible OR it fills ≥ 50 % of the viewport, tab visible.
- **Live** counts page views (random per-view id), not people; it trails real time by ≤ ~1 min (rollup cadence).
- **Asset Optimizer:** all handles are in `fw:ext:asset-optimizer:js_exclude_handles`; the tracker loads `defer` in the footer.
- **Heatmap viewer modes:** clicks · scroll reach · attention · elements · **frustration** (items outlined with rage/dead/error counts; page-level count top-left). `GET /heatmap` returns `friction: [[item, kind, n]]`. The Heatmaps tab accepts `&mode=` to open in a mode (the Frustration tab links with `mode=frustration`).
- **Testing tip:** scroll-reveal animations move buttons while Playwright clicks them, so a `force` click can land on the parent — scroll into view, wait for the animation, then click without `force`.
- **Remove all data** (Settings) drops and recreates the tables and deletes buffer files; deactivation never touches data.
