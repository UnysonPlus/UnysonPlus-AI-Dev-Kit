# shortcodes extension

The core drag-and-drop content-element system — the parent that owns every UnysonPlus page-builder element and the shared styling/animation/icon helper layer. **Active by default:** yes (hidden parent; pulled in automatically by `page-builder` + `wp-shortcodes`, which the theme auto-activates).

## Provides

- **Shortcodes:** the full element catalog (special_heading, text_block, button, icon_box, accordion, tabs, gallery, posts, pricing_table, testimonials, section, column, flexbox, container, and dozens more) — each element is a folder under this extension's `shortcodes/`. Per-element atts + recipes: `../shortcodes/` (one page per element; `../shortcodes/README.md` documents the page-builder node model / JSON tree). `display => false` (never shown as a standalone extension row).
- **Bundled sub-extensions:** `extensions/page-builder` (the visual builder + `page-builder` option type — its own repo) and `extensions/wp-shortcodes` (classic-editor shortcode inserter).
- **Settings/options:** an extension **Settings** page. Key id: `smooth_scroll_global` (site-wide Lenis inertia scroll; per-page control overrides it) under the `smooth_scroll_box`. Read via `fw_get_db_ext_settings_option('shortcodes', '<key>')`.
- **Admin: Shortcodes page (`admin.php?page=fw-shortcodes`):** native WP nav-tabs — **Shortcodes** (enable/disable every element; install a new shortcode or a design pack from a .zip / GitHub — auto-detected by `manifest.json`) and **Design packs** (per-shortcode postboxes: enable/disable any design incl. built-ins, and delete installed packs). To UPDATE a pack, re-upload its .zip on the same page — a same-`design_key` upload triggers a version-comparison **replace confirmation**, then overwrites in place. A shortcode card shows a **"Designs (N)"** shortcut when it carries installed packs.
- **Shared helper layer (`includes/`):** the styling helper (`sc_color_field_compact`, `sc_normalize_color_value`, `sc_build_wrapper_attr`, spacing/alignment field helpers), the central icon renderer (`sc_icon_render`, SVG sanitizer), background-pro, and the animation-field registry that the **Animations** tab and the Animation Engine plug into.
- **Shared Card system (`includes/`, `shortcode-styling-helper.php` + `card-rows/` + `card-preview/`):** the one composable "card = a stack of rows" model reused by every card-style element (Products, Testimonials, Team Member, Posts, …), so a card layout is designed once and behaves identically everywhere.
  - **Card Rows designer** — `sc_card_rows_field($args)` returns an `addable-popup` of drag-sortable ROWS; per element you pass the SLOT choices (`slots => [slug => Label]`) + seeded default rows. Each row picks & orders slots, sets **Direction** (inline / stacked), **Reverse** (flip an inline row without re-ordering), **Distribute** (justify) and **Align**. A slot is "visible" simply by being in a row with content — no separate show/hide toggles. `sc_card_rows_value($atts, $key)` normalises the saved value → `[{ slots[], dir, justify, align, reverse }]`; `sc_card_rows_render($rows, $slot_map, $prefix)` assembles it to HTML (`{prefix}__row {prefix}-row--{dir} {prefix}-j-{justify} {prefix}-a-{align}` + `--reverse`), collapsing empty slots/rows. Composite "molecule" slots (e.g. testimonials **Author** = Name+Position stacked, **Identity** = Image+byline) let a row hold a grouped unit; a structural design can declare **`filter_slots`** (via `sc_render_card`) to claim a slot for its own fixed position so it never double-renders in the row body.
  - **Live card preview** (`includes/card-preview/`) — a schematic wireframe that redraws in the builder as rows/slots change. Drop a `sc_card_preview_mount_html(['heading','note','rows_name'])` mount into an `html-full` option; the shared preview JS/CSS auto-enqueues in every builder/options context (backend post editor + front-end Live Editor). One engine serves every card element.
  - **Card Box Style** — `sc_card_box_style_field($args)` returns a `border-style-picker` of Theme Settings → Components **Box Presets**; `sc_card_box_style_class($atts, $key='box_style')` reads/validates it into a safe `boxp-{slug}` class applied per card (border / corners / shadow / fill + hover effects).
- **Shared button-style helpers (`shortcode-styling-helper.php`):** `sc_button_style_field()` returns a Style-tab option group (Button Style preset, Size, Shape, Width, Alignment, Hover Animation — the same Theme Settings → General → Buttons sources the `[button]` shortcode uses), and `sc_button_style_atts($atts)` turns the saved values into button classes + inline width + `align`. Lets ANY element (first consumer: the WooCommerce Add-to-Cart element) wear a theme button preset without hand-CSS.
- **Arbitrary-value spacing (Tailwind-style `pt-[40px]`, `mb-md-[3.5rem]`, `g-[24px]`):** the fixed spacing scale is Bootstrap-aligned and can't express every value, so a spacing option may hold an ARBITRARY token and the per-page dynamic CSS emits the matching escaped, breakpoint-aware rule (`.pt-\[40px\]{padding-top:40px}`). `sc_sanitize_class()` preserves ONLY the strict arbitrary pattern (`^(m|p|g)(x|y|t|b|s|e|l|r)?(-(sm|md|lg|xl|xxl))?-\[num(px|rem|em|%|vw|vh)\]$` — no XSS surface); the responsive-infix builder handles both scale slugs and arbitrary values; and `sc_get_spacing_select_choices()` keeps arbitrary-NAMED scale entries — so a Spacing-Scale entry named `[40px]` (Theme Settings → Components → Spacing) yields a selectable `pt-[40px]` option. The Site Converter emits a preset slug when captured px lands on the scale, else an exact `pt-[Npx]`, so converted sites capture spacing losslessly. Non-breaking: the scale, containers, gutters and every existing `pt-N` are untouched.
- **Custom-CSS admin-scoper (`includes/theme-settings/miscellaneous-handlers.php`):** `fw_admin_safe_custom_css()` runs ALL Theme Settings **Custom CSS** (hand-written OR Site-Converter-emitted) before it is emitted, rewriting global `body` / `html` rules to front-end-only variants (`body:not(.wp-admin)`, `html:not(:has(.wp-admin))`) while leaving class/id/descendant rules (`.pb-*`, `.upwc-*`) alone. Because that stylesheet is also loaded in wp-admin for the page-builder canvas WYSIWYG, an unscoped top-level `body`/`html` rule (background, overflow, …) used to repaint the editor chrome; this is idempotent and can't recur regardless of who wrote the CSS.
- **Pluggable designs & design packs (`includes/pluggable-designs.php`):** a "design" is a layout variant an element offers in its **Design** option (image-picker). A design-capable element's designs are the UNION of its **built-in** registry (`shortcodes/<tag>/views/designs/registry.php` + `views/designs/<key>.php` partials) and admin-installed **design packs**. A design pack is a ZIP uploaded on the Shortcodes admin page: `manifest.json {pack:1, type:"design", shortcode, design_key, name, version, author, license, vendor_deps?[]}` + `view.php` (render partial) + optional `options.php` (design-scoped option fragment merged into the host's `design_settings` multi-picker) + `static/css/styles.css` / `static/js/script.js` + `img/icon.svg`. Packs install to `uploads/unysonplus/designs/<shortcode>/<design_key>/` (re-uploading the same key = in-place UPDATE). The layer API: `fw_sc_designs($tag[, $include_disabled])`, `fw_sc_design_picker_choices($tag)` (options.php), `fw_sc_design_resolve($tag,$atts)` + `fw_sc_design_partial($tag,$key)` (view.php), `fw_sc_design_enqueue($tag,$key)` (static.php). Enable/disable state lives in the option `fw_sc_design_packs_disabled` (`tag => [disabled keys]`; `default` can never be disabled) via `fw_sc_design_set_enabled()`. Reference element: **testimonials**.
- **Public hooks/filters:** many — e.g. `sc_needs_wrapper`, `sc_build_wrapper_attr` (priority-ordered wrapper builder), `sc_section_background_effects`, `sc_anim_collection_items`, `unysonplus_editor_list_formats`, and the color/preset resolvers. Requires the base `builder` extension.

## Notes / gotchas

- This is a **framework, not a single feature** — most day-to-day work happens in the individual `shortcodes/<name>/` folders; read each element's own `AGENTS.md` before editing (the shortcodes recipe).
- Colors on elements must use `sc_color_field_compact()` (preset picker), never a raw `color-picker` — see the workspace color-option rule.
- Its GitHub repo is `UnysonPlus-Shortcodes-Extension`; the nested page-builder maps to the separate `UnysonPlus-PageBuilder-Extension`.
- The changelog in `manifest.php` is the running record of element features — skim it to see what each element can already do before adding capability.
