# portfolio extension

A full portfolio module: a `fw-portfolio` custom post type (with Categories, optional Tags) plus per-project galleries, rich details meta, archive templates, single-view blocks (details / results / testimonial / prev-next / related) and seven builder elements. **Active by default:** no (enable it under Extensions). Version: 1.0.23.

## Provides

- **Shortcodes:** `[portfolio]` (filterable project grid — grid/masonry/list layouts, AJAX category filtering, load-more pagination, lightbox card mode), `[project_gallery]` (one project's image gallery with the vanilla-JS lightbox), and five single-project template parts: `[project_details]`, `[project_results]`, `[project_testimonial]`, `[project_nav]`, `[related_projects]` → `../shortcodes/` for atts. The parts let a project page be built entirely in the page builder; `[project_nav]`/`[related_projects]` render only on single-project pages. Grids can also use the generic `[posts post_type="fw-portfolio"]`.
- **CPT / taxonomies:** registers `fw-portfolio` (supports title/editor/thumbnail/revisions/page-attributes — the Order field powers `menu_order` sorting) + `fw-portfolio-category` (and, when enabled, a Tags taxonomy); both declare `show_in_rest`. Rewrite slugs are editable on Settings → Permalinks.
- **Archive templates:** the extension ships `views/archive.php` + `views/taxonomy.php` (via `template_include`; a theme `archive-fw-portfolio.php` or a `framework-customizations/extensions/portfolio/views/` override wins). The archive renders a category filter bar of REAL taxonomy links (crawlable, pagination-safe), the settings-driven card grid and numbered pagination.
- **Settings/options:** an extension **Settings** tab (house box+group layout). Key ids: `archive_columns`, `archive_per_page`, `orderby`, `order`, `featured_first`, `archive_filter_bar`; feature switches `enable_gallery`, `enable_project_details`, `enable_tags`; single-view `show_gallery_single`, `single_columns`, `show_meta_single`, `enable_prevnext`, `prevnext_same_category`, `enable_related`, `related_count`, `related_heading`. Read with `->get_setting()` / `->feature_enabled()`. **Every read runs through the `fw:ext:portfolio:setting` filter**, letting the active theme override display settings (the parent theme's Theme Settings → Portfolio tab uses this; see `../theme-settings/portfolio.md`). Unknown keys also flow through the filter, so themes can drive extra display knobs read with code defaults: `archive_gap`, `archive_ratio`, `archive_hover`, `card_show_category`, `card_show_summary`.
- **Per-project meta (Project Details box):** client, URL, completion date, services, role, tools/tech stack, industry, repository URL, short summary, a results/metrics repeater (`project_results`: `[{value,label},…]`), a testimonial (quote + author + company), plus a Featured switch. Side box **Card & Visibility**: a dedicated card thumbnail (`project_card_image`, used by grids instead of the cover image when set) and a **Hide from archives** switch. Featured/hidden are mirrored to queryable `_fw_portfolio_featured` / `_fw_portfolio_hidden` post-meta on save; hidden projects are excluded from the archive, grids and related rows but stay reachable at their URL.
- **Structured data:** single projects emit CreativeWork JSON-LD built from the details meta (`fw_ext_portfolio_jsonld` filter to adjust or return `array()` to disable).
- **Jetpack import:** admin tool at Portfolio → Import converts `jetpack-portfolio` items to Projects, mapping Project Types → portfolio categories (and tags when enabled).
- **AJAX:** `wp_ajax(_nopriv)_fw_portfolio_load` powers the grid's category filters + load-more (nonce `fw-portfolio-load`; args re-validated through `fw_ext_portfolio_sanitize_grid_args()`).

## Notes / gotchas

- Shared render helpers keep the single view, archive views and shortcodes identical: `fw_ext_portfolio_render_gallery()`, `get_project_meta`, `render_project_meta` (+ `heading_tag` arg, default h2 per the heading-order rule), `render_results`, `render_testimonial`, `render_prevnext`, `get_related`, `render_related`, `render_card` (card thumbnail > cover; `link_to` project/lightbox/none), `render_grid` (+ `query_projects`, `render_cards`, `sanitize_grid_args`, `grid_query_export`, `grid_attrs`, `render_archive_filter_links`).
- **Read settings on `init` or later, never during extension boot** — an early read forces Unyson's option-types init before page-builder registers its `page-builder` option type (the 1.0.14 "Undefined option type" regression).
- Card grids share one CSS contract (`fw_ext_portfolio_grid_attrs()`): custom properties `--fw-portfolio-cols/gap/ratio` + classes `fw-portfolio-grid--hover-{zoom|overlay|grayscale|none}`, `--layout-{grid|masonry|list}`, `--ratio-auto`. Masonry is CSS columns (no JS); overlay hover is touch + reduced-motion safe.
- The old jQuery NivoSlider + its assets were removed (1.0.13, breaking) in favor of the CSS-grid gallery + accessible lightbox; lightbox strings are localized via `fwPortfolioLightboxL10n`.
